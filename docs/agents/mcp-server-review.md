# 自带 MCP server 的实现与验收

仅在新增或修改 `demo/mcp-*.mjs` 的路径、目录、读取、子进程或输出行为时使用。开始实现前，写下该 server 的授权范围、会返回的数据、可能的副作用、资源上限；以下各项按实际能力标注适用或不适用。

1. **授权路径**：同时检查请求路径和解析后的真实路径；相对路径、绝对路径、多根、`..`、根内外双向符号链接或目录联接各有明确语义。目录子项的大小等元数据同样受授权边界约束。用合成凭据测试敏感路径的直接访问、别名访问、列举和仅含敏感项的目录。
2. **全部输出**：状态、差异、目录名、成功结果、失败诊断都可能向网页模型披露信息。复用 `src/sensitive-paths.mjs` 的规则；差异或移动涉及两个路径时检查两端。测试既断言合法内容可见，也断言合成凭据和敏感路径不可见。
3. **只读副作用**：调用外部命令前查明它是否会按仓库配置或环境变量执行辅助程序、刷新索引或写缓存。禁用不需要的扩展；用只写测试标记的辅助程序和调用前后状态对比，证明工具调用没有新增写入。
4. **有界读取**：写明限制对象与单位（原始字节、字符、文件数、单帧）；在完整累积或解析之前执行输入限制。涉及文件内容时，同一文件句柄完成类型、大小、内容判定；最多读取上限加一个判定字节，检查读入范围内所有 NUL。成功和失败回填均受限；明确拒绝与已发请求结果不明分别沿用既有语义。
5. **完成证据**：新增能力先用样本证明原来无法满足的需求，修复缺陷先建立修复前失败的反例；每项适用边界还要有正常样本，经真实 `createMcpClient` 调用验证。覆盖恰好上限、超一单位及跨块/多项场景中与改动有关的情况。测试只用隔离目录和假凭据；`PLAN.md` 分开记录单测、浏览器冒烟、真实模型现场验证及未测条件，不把一种证据推断成另一种。
