# openworker 借鉴调研

调研日期：2026-09-30。目标仓库：[andrewyng/openworker](https://github.com/andrewyng/openworker)（OpenWorker，MIT，吴恩达团队开源的 local-first 桌面 AI 同事），固定在 `main` 当时提交 [`c37b7614`](https://github.com/andrewyng/openworker/tree/c37b761499105b9216977f0d68b5e62dac2b3c1c)（2026-09-29）。只读 README、docs/、coworker/ 源码、pyproject.toml、tests/ 目录清单、官网与 [aisuite 内官方 quickstart](https://github.com/andrewyng/aisuite/blob/66c7890c2d68c2d67f41723bc848bb6713d82a9c/docs/openworker-quickstart.md)（钉在 aisuite main 的 `66c7890c`）；未安装依赖、未运行其代码、未连接其服务。技术栈：Python 后端 `coworker/`（引擎/工具/连接器/MCP/沙箱，构建在 [aisuite](https://github.com/andrewyng/aisuite) 上）+ Tauri 桌面壳 `surfaces/gui/`（React/TS）+ Rust 语音侧车 `stt/`；GUI 与后端经本地 server（FastAPI + 每次启动的 sidecar token）通信。[README](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/README.md#L44-L55) · [仓库布局](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/README.md#L121-L135)。它是自建 GUI 的完整桌面产品，与本项目「用网页聊天当模型前端」的路线前提不同；以下按对本项目的潜在价值排序，"值得借鉴"是设计判断，不表示已决定实施。

## 1. 风险分级 + 三层生命周期的审批阶梯（对照 P60/P61 写入门）

上游每个工具调用先过纯函数风险分类（`RiskClass`：read / egress / write_local / exec / external），再由 `PermissionEngine.evaluate()` 按模式（discuss/plan 只读、interactive 默认询问、bypass、auto-approve、custom）+ 参数模式匹配出 `Decision`（allowed / needs_user / human_only / 命中的规则），引擎只把 `needs_user` 路由给审批面。[风险分类](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/risk.py#L18-L23) · [权限引擎](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/permissions.py#L342-L520) · [模式枚举](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/permissions.py#L213-L229)。审批结果是一组带**生命周期**的档位：`once` / `always_tool` / `always_command` / `always_domain` / `readonly_session` / `always_trust`（落盘，跨会话）/ `this_run`（仅当前 run，引擎在 run 结束与中断时统一清空）/ `deny`。[审批结果枚举](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L70-L87) · [run 边界清空](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L415-L430) · [授权落地分支](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L1797-L1815)。每次审批的来龙去脉（用户点批 / 审批器放行 / 规则放行 + 理由）写入审计行并持久化。[审批解决审计](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L1822-L1829)。

本项目 P61 的「会话同意」对应其 `always_tool`；值得对照的是它把「批一次」拆成了 run / session / durable 三档，且**每档的失效点写进引擎语义**（run 结束即清、进程重启等于 run 结束）。若本项目将来出现「一个 ask 任务内反复写同一批文件」的噪音，`this_run` 是比「会话同意」更小的授权单位；其「每个放行都记审计行」也与 Receipt 的动作记录互补。**边界**：上游 `always_trust` 落盘 `risk_overrides.json` 是扩授权面，与本项目「授权冻结只缩不扩」的既定决定相反，不应引入；其 auto-approve 模式由 LLM 审批器代批，前提是有独立的本地模型通道，本项目网页模型就是动作发起者，没有这个前提。

## 2. 审批模式管不住的硬地板：自保护、延迟执行文件、第三方 MCP 下限

上游在 `evaluate()` 最前面放了几层**任何模式与授权都压不下去**的地板：agent 不得写权限系统自身（config.toml、risk_overrides.json、coworker.db、secrets.json 等，shell 命令文本里出现这些路径也拒）；项目内会在"之后某个无害动作"时执行的文件（`.git/hooks/`、`.github/workflows/`、`.vscode/tasks.json`）可以改但必须人看；授权超越会话的工具（save_skill、定时任务增删改）一律 `human_only`。[受保护路径](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/permissions.py#L93-L110) · [项目内延迟执行文件](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/permissions.py#L117-L132) · [持久授权工具](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/permissions.py#L73-L90)。第三方 MCP 工具风险**焊接在 external**：用户 override 只能收紧不能放松，server 配置里的免审批旗标现在只免「卡片」不免「分级」。[MCP 下限](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/risk.py#L90-L114) · [override 只紧不松](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/risk.py#L64-L70)。写路径先做可定位性检查：定位不了的写（未知工具、解析不出文件头的 patch）fail-closed 转人工，绝不带范围外路径自动放行。[写路径提取](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/permissions.py#L157-L179) · [失败关闭](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/permissions.py#L384-L392)。沙箱选择同样 fail-closed：显式选了沙箱而沙箱不可用时**拒绝开会话**而不是静默回退 direct。[选择逻辑](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/sandbox/selection.py#L59-L98)。

本项目已有同构纪律（审批模式不放宽沙箱、授权只缩不扩、无 dryRun 外部写入按需询问）。**可借鉴的具体缺口**是「延迟执行文件」这一维度：P61 风险询问只看「是否覆盖已有内容」，不看「写进去的东西会不会在将来某个动作时被执行」（`.git/hooks`、`package.json` scripts、`.coworker/` 这类策略目录）。若自带 fs server 的写入门后续要细化分级，这是一个有上游先例、又能用纯函数判定的候选维度。**边界**：其受保护路径表绑定自家状态目录布局，本项目对应物是 `~/.file-tool/`（threads.json、watch-checkpoints.json）——当前 MCP server 的授权根由用户指定、一般圈不进状态目录，若未来 host 侧出现审批配置文件，应先补同款地板再扩权。

## 3. 循环失败路径的精细处理（对照 runTurn）

上游 `TurnEngine` 是单轮原语上的流式循环：一个用户 turn 内多轮「模型 ↔ 工具」直到模型不再要工具、撞 `max_iterations`（默认 12）或被中断；低风险工具（metadata `risk_level=low` 且免审批）在同一批里并发执行，写/shell 严格按序。[引擎文档](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L1-L11) · [迭代上限](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L124-L130) · [并发/串行分派](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L1053-L1149)。失败路径区分得很细，与本项目 runTurn 的 stalled / round-limit / driver-error 对照：(a) 回复被输出上限截断且无动作时，注入一次续作提示，最多 2 次后以 `truncated` 结束——明确区分"完成"与"放弃"，而不是当成正常完成。[截断续推](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L753-L810)；(b) 模型输出像工具调用但参数解析失败时，按「截断」还是「坏 JSON」两种原因给不同诊断文案，不把裸 `_raw` 回放进历史（观察到会教模型故意模仿）。[残缺调用诊断](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L1151-L1180)；(c) 中断/重启留下的孤儿 tool_use 用诚实 stub 封口（"无结果，需要就重新发起"），修复会话可继续。[孤儿修复](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L557-L591)；(d) 所有工具结果统一封顶（头+尾+溢出文件指针），模型可见体积在入历史前一次性约束。[结果封顶](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L1917-L1929)。

可借鉴的是 (b)(c) 的**诊断文案语义**：本项目「动作块没被识别」目前靠 last-reply.txt 人工取证，回填给模型的错误信息可以更明确地分「截断」与「标点/格式损坏」两种自纠错指引（后者已有归一化兜底）；(c) 与本项目「未确认断点人工核对、由用户在网页要求导师重新提出动作」几乎同构，验证了该方向。低风险动作并行对本项目价值有限（每轮上限 6 个动作且网页往返是瓶颈）。**边界**：上游能拿到 `finish_reason` 与 usage，网页侧不可得，截断检测只能用字符数/停滞性质近似。

## 4. 会话持久化与可恢复性（对照断点与压缩续接）

上游会话存储 = SQLite 索引（会话/工作区/记忆）+ 每会话一个 **append-only JSONL** 消息日志，只追加新消息不重写历史；session id 用白名单正则并复核解析后路径仍在会话目录内，防路径逃逸；读到截断的坏行跳过而不是让整个会话打不开。[存储布局](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/conversations.py#L1-L9) · [安全 id](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/conversations.py#L22-L34) · [坏行容忍](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/conversations.py#L138-L150)。「always allow」授权随会话持久化（起因是 owner-hit：重启即丢授权）。[授权持久化](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/sessions.py#L28-L36)。中断恢复：重启后 `resume()` 重放**尾部未应答**的 tool calls（已应答的跳过，不双执行），先修孤儿再续循环。[resume](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L535-L555)。长会话自动压缩（OPE-27）：只压缩**出站视图**、持久 transcript 不动；触发 `min(80%×窗口, 250k token)`；保留最近 25%；首条用户消息整段钉住（任务授权永不裁剪）；摘要低于 400 字符或缺 8 个必备段落则拒收重试；attended 失败问人、unattended 自动降级为裁剪最旧 10%。[压缩常量与结构校验](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/compaction.py#L17-L47) · [模块约定](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/compaction.py#L1-L15)。

本项目 watch-checkpoints.json / threads.json 已有原子写与「损坏不覆盖」纪律，上游可借鉴两点：**摘要结构校验**（压缩续接的 ```summary 目前只要求是人确认过的内容，可加「必含小节」约定，避免摘要过薄导致新线程丢任务边界）；**「首条任务消息永不进压缩」** 的原则可以写进压缩续接的提示词约束。**边界**：本项目聊天正文在网站侧、本地不存消息日志，其 JSONL/SQLite 方案没有对应场景；其 resume 的"已应答跳过"依赖 tool_call_id 幂等，网页动作没有稳定 id，本项目的等价物仍是断点 + 人工核对，不能照搬其"不双执行"承诺。

## 5. 模型无关层、connector 机制与桌面集成方式

模型接入：运行时不 import 任何厂商 SDK 接口，只依赖 `ProviderClient` 抽象（单发阻塞、**刻意不带 max_turns**——"循环归 runtime"），配 `ModelCapabilities`（vision/pdf/streaming）做优雅降级，usage 归一化（cache 拆分）。[ProviderClient](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/providers/base.py#L117-L131)。工具层构建在 aisuite 上：JSON schema 生成与 `ToolMetadata`（category/risk_level/requires_approval）复用 aisuite，权限判定不在注册表里而在引擎。[工具注册表](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/tools/registry.py#L1-L14)。connector 是**自建协议**而非 MCP：40 个 `ConnectorDescriptor`（README 写 "25+ integrations"）都是数据驱动的向导描述符（auth 方式、要粘贴的字段、真实 API 校验），底层是各家 SaaS 的 REST API + token/OAuth；仅 jira/monday 两个走 vendor-hosted MCP + OAuth DCR，且工具面是**钉死的子集**——"漂移只能缩能力，不能涨"。[描述符](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/connectors/descriptors.py#L46-L95) · [MCP-backed 字段](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/connectors/descriptors.py#L68-L74)。自定义 MCP server 用官方 Python SDK，每 server 一个常驻 task，支持 stdio/streamable-http/OAuth。[MCP 客户端](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/mcp/client.py#L1-L11)。**桌面集成方式**：Tauri 壳 + 本地 Python server；操作本地应用的能力 = 文件 + 持久 shell（bash/PowerShell REPL，`cd`/env 跨调用保留）+ Playwright 浏览器自动化（**可选依赖**，与本项目同一库）。源码树中没有 accessibility API 或截图+点击式的任意桌面应用操纵。[持久 shell](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/tools/shell.py#L1-L21) · [run_shell 元数据](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/tools/shell.py#L162-L170) · [Playwright 可选](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/connectors/browser_automation.py#L1-L5)。

对本项目的参照价值主要是定位差异：两者都用 Playwright，但上游用它给模型提供浏览器工具，本项目用它驱动聊天网页本身；上游「模型即本地 API 客户端」使其可以做持久 shell、并发工具、token 级压缩，这些都是网页前端路线结构性做不到的，属预期差异而非缺陷。其「MCP 工具面钉死子集、漂移只缩不涨」与本项目的工具目录允许列表思想一致，可作为外部 server 接入文档里的表述先例。**边界**：其 connector 向导、OAuth broker、Slack 触发都是产品面扩张，本项目不引入。

## 6. 依赖规模、测试与治理（参考）

核心 Python 依赖约 20 个（openai/anthropic/google-genai/aisuite/fastapi/httpx/mcp SDK 等），GUI 另有完整 npm 树与 Rust 工具链，浏览器与沙箱是可选 extras——与本项目「零 npm 新增、Node 内置模块优先」是两个量级。[依赖清单](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/pyproject.toml#L12-L58)。测试面值得注意：除常规单测外，`tests/corpora/` 存了分层的**权限语料**（benign / dangerous / injection / permission_gate jsonl + decision_matrix.csv，配 golden 测试），把"每个危险输入都必须被拒"做成回归资产。[语料说明](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/tests/corpora/LAYERED_CORPORA.md)。治理：MIT（GitHub API license 字段确认）；活跃度高（2026-09-30 经 GitHub API：18,364 stars / 2,596 forks / 514 open issues；创建 2026-07-20，最近推送 2026-09-29）；有 SECURITY.md 且把「绕过 human-only 地板或审批门（含提示注入、恶意 MCP 工具）」列为高严重度收录范围。[SECURITY.md](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/SECURITY.md#L1-L25)。

可借鉴的是权限语料思路：本项目写入门（P60/P61）目前靠单测覆盖分支，若后续扩审批维度，可把「动作样本 → 预期审批结果」整理成数据文件 + golden 测试，改动判定逻辑时全量回归。**边界**：其语料围绕命令/路径语义，本项目 host 动作面小得多，先有分支测试再谈语料。

## 不宜照搬

- **OS 级沙箱三件套**（NVIDIA OpenShell 容器 / macOS Seatbelt / Windows 隐藏本地账户 + WFP 过滤）：每会话一容器、代理白名单网络、密钥「缺席而非拒绝」的设计很完整，但需要平台特定安装与系统权限，和本项目「Node 内置模块、零安装门槛」的前提冲突；本项目当前边界（Host Root 硬沙箱 + 四只读动作 + MCP 门控写入）已由用户确认，扩这层属产品方向取舍。[macOS 沙箱](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/docs/macos-sandbox.md#L1-L27) · [Windows 沙箱](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/docs/windows-sandbox.md#L1-L45)。
- **LLM 审批器（auto-approve + 连续 5 次拒绝熔断 + 影子评估）**：前提是存在与动作发起者独立的本地模型与审批卡 UI；本项目网页模型既当运动员又当裁判，不具备该前提，且会引入额外模型费用与不确定判定。[审阅器激活条件](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/engine.py#L1206-L1220)。
- **持久化信任规则（risk_overrides.json）与 40 个 connector / Slack / 云 OAuth broker / remote machines**：前者与「授权冻结只缩不扩」相抵，后者是网络面与维护面的双重扩张，均超出本项目产品边界。
- **直接抄其命令白名单/只读分类器实现**：`readonly.py` 的动词白名单与读目标提取是为「会话级只读 shell 放行」服务的（且明确自称不是沙箱）；本项目 `run` 是按扩展名白名单执行测试文件，语义不同，直接混用会把两套边界都搅浑。[分类器契约](https://github.com/andrewyng/openworker/blob/c37b761499105b9216977f0d68b5e62dac2b3c1c/coworker/readonly.py#L1-L20)。
